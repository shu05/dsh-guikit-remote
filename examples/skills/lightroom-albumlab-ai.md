# Lightroom Classic: AI-обработка плагином AlbumLabClient (0 скриншотов после калибровки)

## Быстрый путь (один прогон ~5 с + время сервера)
1. **Выделить всё**: `gui_click` по миниатюре сетки/фильдстрайпа `(L+150, T+1450)` → `gui_key ctrl+a`. Плагин берёт выделенное; количество видно из текста стартового попапа (UIA), не скриншотом.
2. **Модуль «Обработка»**: `gui_key d` → `gui_wait { mode: window, title: "Обработка" }` (заголовок окна меняется — проверка без скрина).
3. **Меню плагина** (смещения от origin окна L,T; калибровались при окне 2657×1745):
   - «Файл» → `(L+38, T+76)`
   - «Дополнения плагина» → `(L+155, T+732)` (подменю раскрывается вправо)
   - Блок **AlbumlabClient**: «Настройки...» T+660, «Start HTTP Task Client» `(L+942, T+796)`, «Stop HTTP Task Client» T+830, «AI обработать выделенное» T+864, «AI кадрировать» T+898, «AI обработать выделенное и кадрировать» `(L+1072, T+924)`.
   - Порядок: Файл → Дополнения → Start HTTP Task Client; затем снова Файл → Дополнения → AI-пункт. **Скрины не нужны** — координаты стабильны, пока окно не двигали/не ресайзили.
4. **Стартовый попап**: `gui_window list title:"Информация"` → handle → `gui_uia tree` (читается заголовок «AI обработка + кадрирование», текст «Задача отправлена на сервер. Обрабатывается и кадрируется N фото», кнопка «ОК» с rect) → клик центра ОК.
5. **Ждать завершения — только UIA, раз в минуту**: AI-обработка на сервере медленная (минуты/десятки минут). В это время **не делать скриншотов и не гонять vision-распознавание** (GPU занят обработкой фото, не конкурируй). Опрос: `gui_window list title:"Информация"` (или `gui_wait { mode: window, title: "Информация", timeoutMs: 55000 }` циклами) ~1 раз в минуту. Новое окно с тем же заголовком = завершение, handle новый. Текст: «... — завершено. Обработано N фото за T с». Закрыть ОК так же.

## Pitfalls
- Заголовок попапа **всегда «Информация»** и handle каждый раз новый — не переиспользуй старый handle, перевызывай `gui_window list`.
- Попапы плагина — нативные TaskDialog: **UIA полное** (Text + кнопка «ОК»), скриншоты не нужны вообще.
- Меню-попапы Lightroom НЕ видны в `gui_window list` (класс #32768) и без UIA — работать вслепую по калиброванным координатам; при смене позиции/размера окна — один калибровочный скрин области меню.
- Стартовый попап надо закрыть до появления финального (иначе окна «Информация» наложатся и handle-опрос даст не то окно).
- Число «обработано» может быть меньше отправленного — читай текст финального попапа, не догадывайся.
- **Поллинг клиента редкий (~раз в 15 мин)**: при отправке AI-команды сервер может ответить ERROR «Lightroom не опрашивает сервер. Запустите Start HTTP Task Client.» — это НЕ сбой: задача встаёт в очередь и подхватывается на ближайшем поллинге. Попап «Внимание: Не удалось запустить: уже запущен» при повторном Start — норма, клиент работает.
- **Канонический индикатор завершения — появление окна «Информация»**: цикл `gui_wait { mode: window, title: "Информация", timeoutMs: 55000 }` до появления; затем `gui_window list` → handle → `gui_uia tree` → если текст «... — завершено. Обработано N фото за T с» — готово, закрыть ОК; если это стартовый/прогресс-попап — закрыть ОК и продолжить цикл. Логи сервера — только вспомогательная диагностика (батчи по 8, ~80-100 с/батч).
- Двойная отправка команды = две задачи в очереди; сервер обработает обе. Лучше не дублировать.
